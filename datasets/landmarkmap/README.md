# LandMark: Indigenous Peoples' and Community Lands

Global data on lands held or used by Indigenous Peoples and local communities,
from [LandMark](https://landmarkmap.org/).

**Source:** [landmarkmap.org/data-methods/access-data](https://landmarkmap.org/data-methods/access-data)

## Manual download

No automated download - LandMark requires manually requesting/downloading
the data from the source site.

1. Download the "Indigenous and Community Lands" shapefile package from
   [landmarkmap.org/data-methods/access-data](https://landmarkmap.org/data-methods/access-data).
2. Extract it so `raw_dir` contains a `shp/` subdirectory with (at minimum)
   `LandMark_IP_LC_point_public_v<version>.shp` and
   `LandMark_IP_LC_poly_public_v<version>.shp` (plus their `.shx`/`.dbf`/etc.
   sidecar files). The exact version string in the filenames varies by
   release; `main.py` finds them by pattern, not a hardcoded version.

   Note: the source zip is compressed with DEFLATE64, which Python's
   built-in `zipfile` can't extract - use `unzip` or `7z` instead.

## Outputs

The source package bundles two layers with the same attribute schema, which
this flow turns into two separate GeoQuery datasets:

- **Points** (`feature_output_dir/landmarkmap_points.gpkg`) - point
  locations buffered to small polygons (`buffer_meters`, default 100m),
  since GeoQuery's zonal-stats-style processing needs polygon geometry.
  Ingested as a `"feature"` type.
- **Polygons** (`boundary_output_dir/landmarkmap_polygons.gpkg`) - the
  polygon layer as-is (reprojected to EPSG:4326; the source's 3D geometry
  is flattened to 2D). Ingested as a `"boundary"` type.

## Quick start

Review and edit the variables in `config.toml` as needed:

- `raw_dir` - where the manually downloaded/extracted `shp/` directory lives
- `feature_output_dir` / `boundary_output_dir` - output directories for the
  two GeoPackages
- `buffer_meters` - buffer distance applied to points
- `overwrite_process`, if true, overwrites existing outputs rather than
  skipping them

## Ingest

The `*_ingest.json` files in this directory are hand-maintained (not
generated by `main.py`), since the categorical filter values they embed
(`country`, `identity`, `doc_status`) are effectively fixed reference data
for a given release. **The `processing_class`/`processing_options` values
are a first draft modeled on `datasets/acled`'s `filter_and_agg` setup and
have not been verified against the GeoQuery backend** - confirm/adjust them
before these are actually used for ingest.
